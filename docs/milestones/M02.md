## Live Supabase discovery (2026-11-08)

- Connected existing Cubics PostgreSQL project is **ACTIVE_HEALTHY**; populated
  core schema had 2 users, 8 rooms, 9 memberships and 15 widgets. Read-only
  referential checks found **zero orphaned memberships or widgets**.
- The repo's Prisma `User.username` and `User.usernameKey` columns were absent.
  Applied **additive Supabase migration**
  `20261108074105_cubics_add_missing_username_columns`; verified both columns,
  the unique index, unchanged row counts and no default username assignments.
  The exact SQL is tracked in
  [supabase/migrations](../../supabase/migrations/20261108074105_cubics_add_missing_username_columns.sql).
- Privilege verification confirms `anon` and `authenticated` have **no**
  SELECT/INSERT/UPDATE/DELETE grants on the four core tables. RLS is disabled,
  however; [security policy decision #4](https://github.com/ybcole/cubics/issues/4)
  remains open. No RLS was changed.
- **Deployment blocker:** existing `prisma/migrations` history targets SQLite
  while the connected DB and current Prisma schema target PostgreSQL. A
  PostgreSQL migration baseline must be established and rehearsed before running
  `prisma migrate deploy`. The connected DB has real data and is **not** a
  substitute for an isolated staging database.
- Read-only data/ACL inspection and the additive migration do **not** prove
  M02.E1 or M02.E2. Hosted application deployment and rollback remain pending.
  [Full audit](../security/SUPABASE_CUBICS_REVIEW.md).
