## Immediate runtime hardening (defense-in-depth, not authorization)

Changed `socket-server.cjs`, `realtime-room-policy.cjs`, `realtime-identity.cjs` and `realtime-membership.cjs` to enforce exact websocket origins, cryptographic Clerk JWT identity, database-backed authorization of room joins and room packets, scoped signaling and verified chat/cursor identity. The client uses `useAuth().getToken()` and refreshes tokens without routinely interrupting hosted tabs. The browser/canvas remain outside the authority boundary. **Remaining issues**: per-widget owner/host control, media grants, profile separation and full database-backed cross-user REST integration are future-milestone work.

## Critical gates still open

1. Verify production deployment with real Clerk/JWKS, PostgreSQL and multi-account E2E (T01; M03). The M01 signed-JWT/member-check implementation has passed isolated integration tests.
2. Protect native sandbox and user-authorized media capture (T04/T05; M04). T06's unused legacy URL probe has been retired in M01 (HTTP 410); full outbound-policy review remains M04.
3. Eliminate shipped backend secrets (T08; M02).
4. Scan and remediate high/critical dependency findings; make audit failure a hard CI gate (T15).
5. Run real negative HTTP/API authorization, browser profile separation, host/controller privilege tests on the deployed stack (M03/M05/M17); Socket.IO forged-identity and cross-room denials already pass CI.
6. Establish branch protection requiring green security workflow as a merge gate (repo admin configuration may be needed).
