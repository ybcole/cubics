## 2026-11-08 account-bound browser partition patch

[Source change 5ac4bf8](https://github.com/ybcole/cubics/commit/5ac4bf8fd6bf6ff451ea7fe6341aee7459d35e42) adds `getBrowserPartition` as a narrow, sender-validated preload API. On every issuance, Electron reads `/v1/identity` using default-session cookies; a forged expected user ID cannot select another account. The main process checks `will-attach-webview`, validates guest partition on capture/download, revokes old guests on account change and leaves their cookie storage intact. React no longer constructs or guesses account partitions. [Native CI workflow](https://github.com/ybcole/cubics/actions/workflows/native-electron-security.yml) adds forged-identity/switch-negative checks; [policy tests](../../scripts/security/electron-policy.test.cjs) check exact allowlists.

**Note:** the test origin mocks `/v1/identity` and does not prove actual Clerk cookies survive cross-domain auth flows. The existing native runner had prior cancellations and its latest run must be evaluated before checking M04.06/M04.08. Signed/verified macOS and Windows builds and an independent security reviewer remain release blockers. **M04 is intentionally not marked `[COMPLETED]` without those gates.**
