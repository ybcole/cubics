## 2026-11-08 account-bound browser partition patch

[Source change 5ac4bf8](https://github.com/ybcole/cubics/commit/5ac4bf8fd6bf6ff451ea7fe6341aee7459d35e42) adds `getBrowserPartition` as a narrow, sender-validated preload API. On every issuance, Electron reads `/v1/identity` using default-session cookies; a forged expected user ID cannot select another account. The main process checks `will-attach-webview`, validates guest partition on capture/download, revokes old guests on account change and leaves their cookie storage intact. React no longer constructs or guesses account partitions. [Native CI workflow](https://github.com/ybcole/cubics/actions/workflows/native-electron-security.yml) adds forged-identity/switch-negative checks; [policy tests](../../scripts/security/electron-policy.test.cjs) check exact allowlists.

**Note:** the test origin mocks `/v1/identity` and does not prove actual Clerk cookies survive cross-domain auth flows. The existing native runner had prior cancellations and its latest run must be evaluated before checking M04.06/M04.08. Signed/verified macOS and Windows builds and an independent security reviewer remain release blockers. **M04 is intentionally not marked `[COMPLETED]` without those gates.**

### Native follow-up before merge (2026-11-21)

Initial PR #10 CI reached the new native fixture and correctly failed its first blank-window assertion on Linux/macOS. Electron computes `disablePopups` from the webview's attributes before emitting `will-attach-webview`; removing the attribute later does not change that computed preference. The validated attachment now explicitly enables popup dispatch in the main process, retaining per-request popup-manager enforcement and rejecting renderer-provided `allowpopups`. A regression checks this ownership/order. Focused tests: 24 PASS. The native matrix must be rerun against this correction; the initial failed run is not accepted as verification.

### Guest login return-to-tab correction (2026-11-21)

Reported behavior: signing in from a guest tab opened a provider window that stayed on Google's consumer home instead of returning to the tab. `electron/guest-popups.cjs` now tracks authentication entry and confines subsequent top-level navigation to authentication pages or the opening site. A stray navigation closes the child, focuses Cubics and reloads the root guest so the shared-session result lands in place; ordinary link popups are unchanged. Negative/acceptance coverage in `scripts/security/guest-popups.test.cjs` (7 focused tests PASS). Provider policy may still reject embedded authorization; this change does not claim universal Google/Claude sign-in.
